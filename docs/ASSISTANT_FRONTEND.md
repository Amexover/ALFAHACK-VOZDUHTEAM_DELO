# Фронтенд помощника

Раздел `/assistant` встроен в существующие кабинеты React + TypeScript + Vite.
Светлая дизайн-система «дело.» сохранена. Компонент AgentState из пользовательского
промпта находится в `frontend/src/components/ui/agent-state.tsx` с атрибуцией Cojeev / MIT.
Исправлены неэкранированные обратные кавычки в исходном CSS-комментарии;
светлые переменные ограничены компонентом, внешняя загрузка шрифтов заменена
системным шрифтом кабинета. Движение учитывает видимость страницы и reduced motion.

## Что доступно

- Клиент: вопросы о финансировании, рейтинг, подготовка заявки, материалы.
- Сотрудник: сводка выбранной заявки, полнота сведений, черновик ответа, очередь.
- История, пагинация, поиск по загруженным диалогам и удаление с подтверждением.
- Потоковые ответы, отмена, обработка ошибок, повтор с учётом UUID и состояния в БД.
- Markdown, таблицы, копирование, ссылки на источники и чтение материалов.
- База знаний и редакционные публикации доступны даже при отключённой модели.
- Сотрудник может загрузить существующий материал по идентификатору, изменить его
  или опубликовать новый. Сервер проверяет права редактора.
- Контекст компании/заявки, текущий рейтинг, переходы в карточки; ссылки на помощника
  в навигации, обзоре бизнеса и карточках клиента/сотрудника.
- Мобильная история, клавиатурный фокус, Shift+Enter для новой строки.

Контекст сохраняется при создании диалога. Для другой компании или заявки создаётся
отдельный разговор. Данные, ограничения, статусы и права определяет API.
Неполный поток не отображается как завершённый ответ. При потере соединения клиент
сверяет результат с историей, прежде чем повторять запрос. Остановка ответа через
отмену fetch передаётся API прокси-сервером. При падении процесса API незавершённый
ход освобождается после серверного таймаута; интерфейс позволяет проверить состояние.

## Запуск

```powershell
cd frontend
npm ci
# Необязательно: локальный API вместо существующего демонстрационного сервера.
$env:DELO_API_TARGET = "http://127.0.0.1:8000"
npm run dev
```

Откройте адрес Vite, войдите в кабинет и выберите «Помощник».
Для настоящих ответов нужен запущенный API с включённым помощником и сервер Qwen;
настройка описана в [ASSISTANT_BACKEND.md](ASSISTANT_BACKEND.md).
API-ключ модели в браузер не передаётся. При `ASSISTANT_ENABLED=false` отправка
вопросов недоступна, вместо ответа отображается сообщение о подключении.
Фронтенд не генерирует демонстрационные ответы в рабочем режиме.

Прямые ссылки:

```text
/assistant
/assistant?company=2&intent=rating
/assistant?company=2&application=15
/assistant?application=15&intent=application_review
/assistant?conversation=<uuid>
```

Успешно созданный разговор получает постоянный URL, который можно обновить.
Доступ к нему остаётся ограничен владельцем и текущими серверными правами.

## Структура и shadcn

```text
frontend/src/components/ui/agent-state.tsx   — предоставленный компонент
frontend/src/assistant/page.tsx             — диалоги и контекст
frontend/src/assistant/content.tsx          — материалы, источники, редактор
frontend/src/assistant/stream.ts            — чтение POST/SSE
frontend/src/assistant/id.ts                — UUID, в том числе на HTTP demo-хостах
frontend/src/assistant/entry.tsx             — ссылки и встраиваемое приглашение
frontend/src/assistant/types.ts             — контракт API
frontend/src/assistant/styles.css           — адаптивные стили
frontend/src/tailwind.css                   — Tailwind v4 и семантические цвета
frontend/src/lib/utils.ts                   — cn / clsx / tailwind-merge
frontend/components.json                    — конфигурация shadcn
```

Алиас `@/` указывает на `src/` в TypeScript и Vite. Каталог `src/components/ui`
нужен для стандартных импортов `@/components/ui/...` и установки компонентов shadcn.
Tailwind v4 подключён плагином Vite. Preflight не включён, чтобы сохранить reset
существующего кабинета. Повторная инициализация проекта или запуск shadcn init не нужны.

## Проверка

```powershell
cd frontend
npm run check
npm run build
npx playwright install chromium
npm run test:assistant
```

Для E2E нужны Python и зависимости существующего backend. По умолчанию используется
`backend/.venv`; другой интерпретатор задаётся переменной `DELO_TEST_PYTHON`.
Уже установленный Chromium можно указать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

Playwright сам поднимает Vite на 5177 и изолированный API на 8017. Тестовая БД создаётся
в `frontend/test-results/`, рабочие базы не используются. Только в тестовом сервере
инференс заменяется управляемым двойником; проверяются реальные авторизация, контексты,
сохранение ходов, инструменты, источники, SSE и редактор материалов. Это проверка
интеграции интерфейса, а не качества ответов Qwen. Скриншоты — в
`frontend/test-results/screenshots/`.

Сборка не публикуется автоматически. Production использует существующий nginx
и тот же `/api`; конфигурация SSE уже добавлена в `frontend/nginx.conf`.
