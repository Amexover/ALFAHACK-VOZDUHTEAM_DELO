# Отчёт: frontend «Дело», вариант 4

21 октября 2026. Работа выполнена по выбранному варианту 4 / Apple и фактическому контракту существующей серверной части FastAPI. Первоначально публикация на GitHub была отложена. Теперь исходники доступны в публичном репозитории https://github.com/Amexover/ALFAHACK-VOZDUHTEAM_DELO; проверяемая версия — тег `v1.0.2`.

## Результат

Создано React + TypeScript приложение с кабинетами клиента и сотрудника. Основной путь работает с настоящим API и PostgreSQL, а не с локальным набором экранов. На сервере nginx раздаёт frontend на порту 80 и проксирует API по тому же адресу. Сессионная cookie httpOnly, токен не хранится в localStorage.

Рабочий адрес: http://195.133.41.30. Документация API: http://195.133.41.30/docs.

## Что реализовано

### Клиент

- Вход, демонстрационные роли, отдельный второй клиент, выход и восстановление сессии.
- Выбор и добавление бизнеса, проверка формата ОГРН/ОГРНИП, сохранение последнего выбранного бизнеса отдельно по пользователям.
- Главная компании: рейтинг, недоступный рейтинг, действующие кредиты, текущие заявки и прошлые обращения.
- Новый кредит: сумма и срок, серверный пересчёт с debounce, два продукта без переименований, сохранение параметров.
- Рефинансирование: выбор действующего кредита, сумма по остатку долга, новый срок, сравнение ставки и платежей, предупреждение о невыгодной предварительной ставке.
- Анкета: пять полей, форматирование чисел, ошибки рядом с полями, «Сохранить и выйти», восстановление серверного шага.
- Объяснение синтетических проверок, сводка с возвратом к конкретному разделу, подтверждение перед отправкой.
- Отправка с блокировкой повторного нажатия; номер, статус, этапы и история от сервера.
- Ответ на запрос банка внутри продукта, сравнение встречного предложения, дополнение для повторного рассмотрения.
- Принятие с подтверждением, завершение без утверждения о фактической выдаче, понятный отказ.
- Шесть материалов с серверным порядком, полный текст статьи и справка внутри кабинета.

### Сотрудник

- Отдельная маршрутизация по роли и очередь отправленных заявок без черновиков.
- Поиск по компании/номеру и фильтры «Все», «На рассмотрении», «Нужны сведения», «Решённые».
- Карточка: анкета, параметры, результаты симуляторов, долговая нагрузка и рекомендация отдельно от решения.
- Запрос сведений с выбором полей, просмотр ответа, одобрение, другие условия и отказ с понятной причиной.
- Подтверждение каждого действия с номером заявки и условиями; после сохранения отображается ответ сервера.
- Для закрытых статусов действия недоступны; текст и история сохраняются.

### Оформление и качество

- Сохранены композиция и визуальный язык выбранного варианта: системная типографика, светлая основа, белые рабочие поверхности, компактная шапка и синий акцент.
- Адаптивные формы, таблица сотрудника с локальной прокруткой, видимый focus, подписи полей, skip link и reduced-motion.
- Диалоги используют нативный dialog. Escape закрывает окно, фокус возвращается к исходному элементу. Во время выполняющегося подтверждения окно не закрывается преждевременно.
- Загрузка, ошибка связи, повтор чтения/расчёта, пустые состояния и серверные ошибки не заменяются фиктивными данными.
- Цена/платёж связаны с конкретными параметрами расчёта. При недопустимом вводе или сбое API старые значения скрываются, предусмотрен повтор запроса.
- Исходники отформатированы, TypeScript strict, зависимости зафиксированы package-lock.json. В runtime нет внешних шрифтов, CDN-иконок, платных API и LLM.

Файлы доказательств: `docs/qa/http-smoke.txt`, `postgres-results.jsonl`, `pricing-recovery.json`, `content-keyboard.json`. Визуальные материалы передаются отдельно в папке reports/screenshots на сервере.

Полная Linux Docker-сборка из исходников и запуск трёх компонентов были успешно проверены на изолированном комплекте. Повторную полную сборку при одновременно работающих основном и тестовом контурах остановили из-за давления на память VPS (889 MiB, без swap). Финальные изменения собирались локально и проверялись на VPS как статическая сборка в nginx. Для сборки на обычном ПК README рекомендует не менее 2 ГБ свободной памяти. Тестовые контейнеры после проверки остановлены и удалены, тестовый volume сохранён.

## Передаваемый комплект

- Активный frontend: `/opt/delo/frontend`.
- Дополнение к исходному Compose сервера: `/opt/delo/deploy/compose.frontend.yml`.
- Полные исходники и единый Compose для будущей передачи команде: `/opt/delo/delivery`.
- Отчёты: `/opt/delo/reports/FRONTEND_REPORT.md` и `/opt/delo/reports/METHOD_COMPLIANCE.md`.
- Исходный backend остаётся в `/opt/delo/backend`, его рабочая `.env` не перезаписывается.
- Версия файлов и контрольные суммы: `RELEASE.json` и архив в `/opt/delo/releases`.
- README, архитектура/ER/состояния, OpenAPI, Postman-коллекция, 29 примеров, тестовые сценарии, THIRD_PARTY_NOTICES и обоснование границ MVP входят в delivery.

В общей PostgreSQL-базе оставлены только результаты синтетического браузерного прогона: завершённый новый кредит и отказ по рефинансированию. Другие тестовые заявки создавались в отдельном PostgreSQL. Данные остальных участников не сбрасывались.

## Что осталось до уверенной сдачи MVP

1. **Закрыть demo-операции на общем сервере.** Сейчас исходный backend разрешает reset/bureau без авторизации, если включён DEMO_TOOLS_ENABLED. На локальном комплекте по умолчанию false, но существующую `.env` VPS в рамках frontend-задачи не меняли.
2. **Исправить backend-валидацию.** Проверять целую анкету после info-response/supplement и перед решением; требовать причину одобрения на API; устранить гонку создания активных черновиков. Интерфейс ограничивает корректный пользовательский путь, но прямой API по-прежнему можно обойти.
3. **Договориться о границах и пройти финальную защиту.** Документы, подписание, выдача, настоящий реестр и LLM отсутствуют намеренно. Путь до результата связан; эти допущения надо объяснить экспертам.
4. **Дособрать эксплуатацию:** домен/HTTPS, API healthcheck, резервные копии и проверка восстановления, миграции. Нагрузку, конкурентность и аварийное отключение всего сервера ещё не проверяли.
5. **Проверить UX с людьми и запуск на другом ПК.** Сценарии подготовлены, но интервью и наблюдаемые пользовательские сессии не проводились. Нет проверки на физических телефонах и во всех браузерах.
6. **После обсуждения команда публикует GitHub**, сохраняет историю, фиксирует commit/tag до дедлайна и выдаёт alfa-hack-2026 доступ, если репозиторий приватный. По указанию пользователя публикация сейчас не выполняется.

Подробная сверка каждого условия методички со страницами находится в METHOD_COMPLIANCE.md. Основной функциональный прототип работает, но все условия финальной сдачи и промышленной безопасности пока не закрыты.
