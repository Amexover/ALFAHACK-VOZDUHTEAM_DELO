# Сценарии приёмки

Только синтетические данные. Не вызывать reset на общем стенде во время работы других участников. Для независимой проверки использовать локальный запуск с новым Docker volume; существующий volume не удалять.

## Новый кредит и уточнение

1. Войти alexey/demo. Выбрать ИП Морозов; проверить рейтинг 820 и существующий кредит.
2. Открыть «Взять новый кредит» → «Новый кредит». 1 500 000 ₽, 24 месяца → 18%, 74 886 ₽. 25 месяцев → 20%. Превышение лимита ИП 3 млн должно отклоняться.
3. Выбрать «Покупка оборудования». Условия не меняются.
4. Нажать «Продолжить» с пустой анкетой: показаны ошибки, перехода нет. Заполнить пять полей, «Сохранить и выйти». Заново открыть черновик: сведения сохранились.
5. Пройти объяснение проверок и сводку; ссылки «Изменить» возвращают на выбранный блок. Без подтверждения кнопка отправки недоступна.
6. Отправить заявку; получить номер и серверный статус. Пока запрос выполняется, повторный клик недоступен.
7. Выйти, войти staff/demo. Открыть заявку. Видны проверки, рекомендация и анкета. Запросить выручку; проверить диалог подтверждения.
8. Войти alexey, ответить на вопрос и заполнить запрошенное поле. Вопрос и ответ остаются в истории.
9. Войти staff. Предложить 1 200 000 ₽, 24 месяца, 19,5%, указать причину. Проверить параметры перед подтверждением.
10. Войти alexey: запрошенные и предложенные условия показаны отдельно, платёж предложения 60 782 ₽. Принять и подтвердить. Обновить страницу: COMPLETED и история сохранились, кнопки повторного принятия нет. Выдача денег не заявлена.

## Рефинансирование

1. У «Маяк Трейд» действующих кредитов нет. Ветка рефинансирования показывает объяснение и действие «Оформить новый кредит».
2. У «Вектор-Станок» выбрать кредит на оборудование: сумма автоматически равна остатку 2 000 000 ₽, поля её изменения нет.
3. Срок 30 месяцев → предварительная ставка 28% против существующих 23%; интерфейс предупреждает, что ставка не ниже текущей. Не обещает экономию из-за меньшего платежа.
4. Заполнить анкету, отправить; сотрудник может отказать с понятной причиной. Клиент видит отказ и историю, кнопки принятия нет.
5. Отдельно проверить положительное предложение рефинансирования и предупреждение об остатке, если банк предложил покрыть не весь долг.

## Одобрение и возврат встречного предложения

- Сотрудник выбирает «Одобрить»: параметры не редактируются. Пояснение обязательно в интерфейсе. После подтверждения клиент видит предложение и принимает его.
- При встречном предложении «Вернуться к заявке» требует текст дополнения; пустые необязательные поля не отправляются. Старое предложение аннулируется, возвращается рассмотрение.

## Доступ, контент и ошибки

- Maria видит только свои компании; прямой URL чужой заявки возвращает ошибку доступа без раскрытия содержимого.
- Клиент по /staff и сотрудник по клиентским маршрутам перенаправляются в собственный кабинет; backend дополнительно проверяет роль.
- Неверный пароль оставляет логин и введённые данные, показывает понятное сообщение.
- Добавление компании проверяет длину номера и название; при ошибке форма остаётся открытой.
- Смена компании меняет рейтинг, кредиты и первые новости. После выбора оборудования в черновике приоритет получает материал по оборудованию. Статья открывается полностью; справка доступна внутри кабинета.
- Внешняя ошибка/отсутствие сети не очищают форму. На экранах чтения есть «Попробовать снова».
- Проверить клавиатуру, Escape и возврат фокуса в диалогах, 390 px, рабочую ширину и отсутствие горизонтального переполнения страницы.

## Автоматические проверки

- `cd frontend && npm ci && npm run build` — TypeScript и production build.
- `cd frontend && BASE_URL=http://localhost npm run smoke` — HTML, ассеты, глубокий маршрут, OpenAPI, health, синтетический вход, роли, чужая компания, расчёт, лимит, 6 новостей и справка. Без создания/сброса заявок.
- `docker compose exec -e DATABASE_URL=sqlite:///:memory: api python -m pytest -q -p no:cacheprovider` — штатные тесты backend на временной SQLite-базе, не на рабочем PostgreSQL.
