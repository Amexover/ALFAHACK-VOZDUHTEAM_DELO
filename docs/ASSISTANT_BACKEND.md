# Бэкенд ИИ-помощника — Qwen3.8-27B

Реализация от 22.10.2026. Встроена в существующий FastAPI; использует его авторизацию,
компании, заявки, расчёт условий и версионированный движок скоринга. Общие роли, статусы,
события и существующие API не меняются. Фронтенд чата в эту поставку не входит.

## Возможности

| Клиент | Сотрудник |
|---|---|
| Базовые вопросы и поиск по правилам продукта | Сводка выбранной отправленной заявки |
| Объяснение рейтинга выбранной компании | Разбор факторов версионированного скоринга |
| Рекомендации по доступным данным | Выявление недостающих сведений |
| Предварительный расчёт через сервер | Черновик ответа клиенту |
| Подбор опубликованных материалов | Просмотр последних 20 заявок через инструмент |

У каждого диалога зафиксированы владелец, роль, компания и заявка. Для смены компании
создаётся новый диалог. Сотруднику нельзя выбрать компанию без отправленной заявки;
черновики клиентов сотруднику недоступны. Диалоги сотрудников приватны для их владельца.
Клиент не получает внутренние баллы, служебную базу знаний или чужие данные.

Рейтинг бюро 0–1000 отличается от внутреннего балла заявки 0–100. Сотрудник получает
оценку существующего движка, в том числе сохранённый снимок после решения. Модель её
не рассчитывает. Инструменты модели не изменяют заявку и не принимают банковские решения.

## Подключение инференса

Веса не включены в репозиторий. Сервис приложения и GPU-инференс запускаются отдельно.
Контракт инференса: `GET /v1/models`, `POST /v1/chat/completions`, потоковый протокол
с `delta.content`, `delta.tool_calls`, `finish_reason` и необязательным `usage`.

Параметры в окружении API:

```dotenv
ASSISTANT_ENABLED=true
ASSISTANT_MODEL=Qwen/Qwen3.8-27B
ASSISTANT_BASE_URL=http://your-inference-host:8000/v1
ASSISTANT_API_KEY=replace-with-your-inference-service-key
```

`BASE_URL` должен быть доступен **из контейнера API**, а не только из браузера.
При локальном запуске Python на Windows обычно используется `http://localhost:8001/v1`;
из Compose для модели на хосте — `http://host.docker.internal:8001/v1`.
Удалённый сервер подключайте по HTTPS или через защищённую частную сеть. API-ключ
доступен только бэкенду и не возвращается фронтенду. Редиректы и системные HTTP-прокси
в адаптере отключены; адрес модели задаёт администратор, пользователь чата его не меняет.

Для собственного Linux-хоста с NVIDIA GPU подготовлен Compose override:

```sh
# В .env задайте ASSISTANT_API_KEY; NVIDIA Container Toolkit должен быть установлен.
docker compose -f docker-compose.yml -f deploy/compose.assistant.yml --profile assistant up -d --build
docker compose -f docker-compose.yml -f deploy/compose.assistant.yml logs -f qwen
```

По умолчанию override загружает оригинальные BF16-веса и ориентирован на GPU класса
80 ГБ; фактическую ёмкость и скорость нужно проверить на выбранном оборудовании.
Контекст ограничен 32768 токенами, одновременных последовательностей — 4. Порт инференса
не публикуется наружу. API не зависит от его готовности: кредитный кабинет продолжает
работать, пока модель загружается или недоступна.

Образ задаётся `QWEN_VLLM_IMAGE` (по умолчанию `vllm/vllm-openai:latest`). После проверки
на выбранном GPU зафиксируйте рабочий тег или digest. `QWEN_TENSOR_PARALLEL_SIZE` задаёт
число GPU. Квантизованные веса и их ядра зависят от оборудования и в этом override
автоматически не выбираются.

Конфигурация соответствует официальным [карточке Qwen](https://huggingface.co/Qwen/Qwen3.8-27B)
и [инструкции vLLM](https://recipes.vllm.ai/Qwen/Qwen3.8-27B): используются
`--reasoning-parser qwen3`, `--enable-auto-tool-choice`, `--tool-call-parser qwen3_coder`.
Запросы отключают thinking и сохранение скрытых рассуждений. Поле reasoning не передаётся
в интерфейс; дополнительный фильтр удаляет теги `<think>` при ошибочной настройке сервера.

### Миграция существующей базы

Сделайте резервную копию, затем из контейнера API выполните:

```sh
docker compose exec api python -m alembic upgrade head
```

Ревизия `20261022_03` добавляет только `assistant_conversations`, `assistant_turns`,
`assistant_documents` и индексы. Повторный upgrade безопасен, в том числе если таблицы
уже создал существующий демонстрационный startup `create_all()`.

Для новой базы текущий проект создаёт базовую схему при первом запуске приложения;
после этого выполняется upgrade. Унаследованная цепочка Alembic не создаёт исходные
банковские таблицы с нуля. Не запускайте откат на рабочей базе без резервной копии:
`alembic downgrade 20261022_02` удалит историю и материалы помощника, сохранив заявки,
компании, пользователей и скоринг.

## Контракт для фронтенда

Авторизация: существующая cookie-сессия либо `Authorization: Bearer <token>`.
Все маршруты ниже начинаются с `/api/assistant`.

| Метод и путь | Назначение |
|---|---|
| `GET /config` | Доступность, модель, роль, сценарии и подсказки |
| `GET /health` | Проверка соединения и наличия выбранной модели |
| `POST /conversations` | Создать диалог, 201 |
| `GET /conversations?limit=20&offset=0` | Диалоги владельца, новые сверху; фильтры `company_id`, `application_id` |
| `GET /conversations/{id}` | Контекст и метаданные диалога |
| `DELETE /conversations/{id}` | Удалить собственный диалог и его сообщения, 204 |
| `GET /conversations/{id}/messages?limit=30&offset=0` | Страница последних сообщений, внутри страницы — от старых к новым |
| `POST /conversations/{id}/messages` | Обычный JSON-ответ |
| `POST /conversations/{id}/messages/stream` | Поток SSE через `fetch` |
| `GET /knowledge?q=рейтинг` | Поиск в доступной роли базе знаний |
| `GET /knowledge/{slug}` | Материал целиком |
| `PUT /knowledge/{slug}` | Опубликовать/обновить материал; андеррайтер или прежняя учётная запись сотрудника |
| `DELETE /knowledge/{slug}` | Удалить опубликованный материал; те же права |
| `GET /news?q=оборудование` | Подбор публикаций с датами и признаками демонстрационных данных |

Создание клиентского диалога:

```json
{"company_id": 1, "title": "Кредитный рейтинг"}
```

Сотрудник выбирает заявку: `{"application_id": 12, "title": "Разбор заявки"}`.
Для общих вопросов допустим `{}`. Сервер сам определяет роль — передать свою роль,
system prompt, историю или идентификатор чужого пользователя в запросе нельзя.

Отправка сообщения:

```json
{
  "request_id": "55e834e1-3e17-4650-8738-196c15ebfb99",
  "content": "Объясни рейтинг выбранной компании",
  "intent": "rating"
}
```

`request_id` — UUID, созданный фронтендом один раз для этого сообщения. Доступные intent:
`chat`, `rating`, `advice`, `news`; сотруднику также `application_review`, `draft_reply`
(последние два требуют выбранной заявки). Повтор завершённого запроса возвращает
сохранённый результат без нового вызова модели. Тот же UUID с другим текстом или intent
даёт 409. После неуспешной попытки для нового запуска используйте новый UUID.

Ответ `TurnOut`:

```json
{
  "id": "uuid",
  "request_id": "uuid",
  "status": "completed",
  "intent": "rating",
  "user_content": "Объясни рейтинг выбранной компании",
  "assistant_content": "... [rating]",
  "sources": [{"id": "rating", "title": "Текущий рейтинг бюро и кредиты компании", "kind": "bank_data", "url": "/api/companies/1/dashboard", "published_at": "2026-10-22T12:00:00Z", "is_demo": true, "excerpt": "..."}],
  "tool_calls": [{"name": "get_company", "ok": true}],
  "usage": {"prompt_tokens": 100, "completion_tokens": 50, "total_tokens": 150},
  "model": "Qwen/Qwen3.8-27B",
  "error_code": null,
  "latency_ms": 1500,
  "created_at": "2026-10-22T12:00:00Z",
  "finished_at": "2026-10-22T12:00:01.500Z"
}
```

`sources` — материалы, предоставленные модели, а не доказательство правильности каждого
предложения. Ссылки вида `[rating]`, `[scoring]`, `[doc:credit-rating:0]` можно сопоставлять
с этим массивом. Не превращайте несуществующий идентификатор в ссылку. Текст и Markdown
модели рендерьте с экранированием HTML; внешние ссылки — только http/https.
`bank_data.published_at` обозначает время чтения сервисом; дата самого рейтинга находится
в банковском контексте. `usage` может быть пустым, если сервер инференса не отдаёт счётчики.

### Потоковый интерфейс

`POST .../messages/stream` принимает то же тело. Используйте `fetch` с чтением
`response.body`, поскольку браузерный `EventSource` не поддерживает POST.
Разделитель SSE — пустая строка, JSON находится в строке `data:`.

```text
event: start
data: {"type":"start","turn_id":"uuid","model":"Qwen/Qwen3.8-27B"}

event: sources
data: {"type":"sources","items":[]}

event: delta
data: {"type":"delta","text":"Рейтинг компании"}

event: tool
data: {"type":"tool","name":"calculate_quote","ok":true}

event: done
data: {"type":"done","turn":{}}
```

Порядок `delta`, `tool`, обновлений `sources` зависит от вызовов инструментов.
Показывайте дельты временно и заменяйте их сохранённым `done.turn.assistant_content`.
При `error` пометьте ответ неуспешным; частичный текст не считается завершённым и
не сохраняется как ответ помощника. Ошибка после открытия потока приходит событием
`error` с `code`, `message`, `status`, `turn_id`; HTTP-статус потока уже 200.
Проверки до открытия потока возвращают обычную HTTP-ошибку.
Раз в 10 секунд ожидания приходит комментарий `: heartbeat`. При повторе завершённого
UUID поток отдаёт только `done` с `replayed: true`. Nginx настроен без буферизации.

## База знаний и новости

Встроенные ответы формируются из каталога продуктов, серверных лимитов, справки и
статусов. Они не редактируются через публикацию документов. Дополнительные документы
разбиваются на перекрывающиеся фрагменты и ищутся по лексическому сходству с учётом
частых русских окончаний. Это прозрачный ограниченный RAG без отдельной embedding-модели;
в этой версии максимум 500 дополнительных материалов по 40000 символов.

Пример публикации материала сотрудником:

```json
{
  "title": "Как подготовить сведения о выручке",
  "body": "Текст утверждённой инструкции...",
  "audience": "client",
  "kind": "knowledge",
  "source_url": null,
  "published_at": null
}
```

`audience=client` видят обе роли, `audience=staff` — только сотрудники.
Slug — строчные латинские буквы, цифры и дефисы, начинается с буквы.

Для новости задайте `kind=news`, ссылку `source_url` и `published_at` с часовым поясом,
не из будущего. Сервис не посещает произвольные URL и не выполняет инструкции из текста.
Публикации загружает редактор через этот API; автоматический интернет-поиск не подключён.
Если публикаций нет, возвращаются существующие шесть демонстрационных материалов с
`is_demo=true`, без выдуманных дат. Поле `has_real_news` означает наличие загруженных
редактором публикаций с источником и датой; достоверность источника редактор проверяет
до загрузки. Сервис не выдаёт этот флаг за автоматический фактчекинг или свежесть новости.

## Ограничения, ошибки и наблюдаемость

По умолчанию: 6000 символов вопроса, 8 завершённых ходов истории в контексте,
24000 символов истории, 65000 символов полного начального запроса; максимум 2048
выходных токенов за вызов, 3 раунда инструментов и финальный ответ без инструментов.
Максимум 6 вызовов инструментов за раунд. Изменяются через `ASSISTANT_HISTORY_TURNS`,
`ASSISTANT_MAX_OUTPUT_TOKENS`, `ASSISTANT_MAX_TOOL_ROUNDS` и другие поля
`app/assistant/config.py`. Эти лимиты символов не заменяют подсчёт токенов в инференсе;
32K контекст выбран с запасом для русского текста и служебных результатов.

Защита от параллельных дублей и лимиты работают через БД между процессами API:
12 новых сообщений в минуту на пользователя, 2 одновременных ответа, 100 диалогов.
В одном диалоге обрабатывается одно сообщение за раз. Таймаут одного HTTP-вызова —
90 секунд, всего хода — 180 секунд. При обрыве клиента ход помечается неуспешным;
после падения процесса аренда истекает через общий таймаут плюс 30 секунд. Следующий
новый запрос восстанавливает состояние; поздний старый процесс не перезаписывает ответ.

Ошибки имеют существующий формат `{"error":{"code":"...","message":"...","fields":{}}}`:
401 — нет сессии, 403 — другой режим, 404 — чужой/несуществующий объект,
409 — занято или конфликт UUID, 422 — параметры/контекст, 429 — лимиты,
502 — некорректный/незавершённый ответ модели, 503 — отключено/нет соединения,
504 — таймаут. Ошибка модели не подменяется выдуманным успешным ответом.

В таблице ходов сохраняются статус, модель, счётчики токенов, задержка, предоставленные
источники и названия инструментов. Prompts, банковские данные и API-ключи не пишутся
в журналы. Тексты диалога хранятся в БД; пользователь может удалить свой диалог.
Автоматическая политика хранения и банковская production-аттестация в эту поставку не входят.

## Проверка

```sh
cd backend
python -m pytest -q -p no:cacheprovider
python scripts/check_openapi_contract.py
```

Тесты помощника используют управляемый двойник Qwen и HTTP MockTransport: проверяют
авторизацию, изоляцию компаний, доступ к внутреннему скорингу, RAG, новости, математику,
отказы недоступным инструментам, историю, UUID, SSE, сбои, отмену, лимиты и восстановление.
Они не являются замером качества Qwen на банковских вопросах.

После подключения реального GPU-сервера:

```sh
export DELO_URL=http://localhost:8000
export DELO_LOGIN=alexey
export DELO_PASSWORD=demo
python scripts/assistant_smoke.py
```

Smoke выполняет настоящий JSON- и SSE-запрос, проверяет повтор UUID и удаляет только
созданные им диалоги. Используйте демонстрационные учётные данные и синтетическую базу.
После него отдельно оцените модель на русскоязычных вопросах, ошибках скоринга,
попытках prompt injection и черновиках ответов сотрудника.
