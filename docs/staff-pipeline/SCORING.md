# Скоринг отдела — тикет 03

Набор `RS-2026.10.1` описан данными в `backend/app/staff_pipeline/scoring.py`.
Это демонстрационные правила проекта, а не действующая кредитная политика банка.
Рекомендация помогает сотруднику принять решение и сама статус заявки не меняет.

## Расчёт

Начальный балл — 30. У каждого правила применяется первая подходящая полоса.
Итог — сумма начального балла и вкладов, ограниченная диапазоном 0–100.
От 80 баллов — `APPROVE`, от 40 до 80 — `MANUAL`, ниже 40 — `REJECT`.
Если нет рейтинга, положительной выручки или срока работы бизнеса, рекомендация —
`MANUAL`. `fired` означает, что требование правила выполнено; отрицательный вклад
может быть у `fired: false`. Правило всё равно участвует в сумме.

| Правило | Полосы и вклад |
|---|---|
| Рейтинг бюро | ≥750: +30; ≥650: +18; ≥500: +4; ≥300: −25; ниже: −45; нет данных: 0 |
| Долговая нагрузка | <50%: +12; ≤80%: 0; ≤100%: −30; выше: −45; нет выручки: 0 |
| Срок бизнеса | Достаточный: +10; недостаточный: −20; не указан: 0 |
| Полнота анкеты | Все пять полей: +10; отсутствуют 1–2: −10; отсутствуют 3–5: −20 |
| Сумма / месячная выручка | ≤1: +8; ≤3: 0; ≤6: −15; выше: −30; нет выручки: 0 |

Долговая нагрузка = (действующие месячные платежи + новый платёж) / месячная выручка.
Числа сравниваются с порогами до округления; округляется только поясняющий текст.
Для суммы до 1 млн рублей включительно нужно 6 месяцев работы, до 3 млн включительно —
12, выше — 24. Недостаточный срок даёт готовую причину `SHORT_HISTORY` из прежнего
справочника отказов. Нулевая долговая нагрузка и нулевой срок — заполненные поля.

`Rule` описывает факт и последовательность `Band`; операции сравнения общие для всех
правил. Новое правило по существующему факту добавляется в `RULESET` без изменения
`apply_rules`. Для нового источника данных нужно дополнить сбор фактов. При изменении
правил, порогов или баллов меняется `RULESET_VERSION`.

## Снимки и жизненный цикл

Первое попадание в очередь или карточку сотрудника создаёт `ON_INTAKE` в таблице
`score_snapshots`. При одобрении, отказе и других условиях создаётся `ON_DECISION`
в одной транзакции с решением. Неуспешное решение не оставляет снимка решения.
Снимок содержит факты, баллы, разбор, рекомендацию и версию. Его идентификатор также
записывается во внутреннее событие `DECISION_MADE`.

Снимок решения оценивает запрошенные условия и данные, на основании которых сотрудник
решал, в том числе при встречном предложении. Оценка альтернативных суммы и срока
доступна через предварительный пересчёт; само предложение хранится в прежнем решении.

До решения `/scoring` возвращает живую оценку. После решения возвращает последний
снимок решения: смена правил, подписей рекомендаций или данных бюро его не меняет.
Дополнение клиентом после встречного предложения возвращает живой расчёт, а повторное
решение добавляет новый снимок. Старые снимки сохраняются.

Для заявок, уже находившихся в конвейере до Т3, первое открытие `/scoring` сохраняет
снимок текущих данных, если снимков ещё нет. Исторические данные до внедрения восстановить
нельзя: такой снимок имеет причину `ON_INTAKE` и реальное время создания, а не время
старого решения. Для завершённой заявки без снимка решения используется этот снимок.

ORM запрещает изменение и удаление снимков при `flush`. Это защита штатного кода,
а не SQL-триггер: прямые SQL-запросы администратора ею не ограничены. Новая миграция
не нужна — таблица создана в тикете 01.

## API и совместимость

Разбор приходит отдельным запросом `/api/staff/applications/{id}/scoring`, согласно
согласованному контракту. Старый блок `scoring` в карточке сохраняет прежние поля и
алгоритм; новый интерфейс использует отдельную ручку для полной оценки.
Клиенту ни разбор, ни внутренние события не выдаются. Старые статусы, роли и общие
события не расширяются; существующие ручки сотрудника и клиентские файлы не меняются.

`POST .../scoring/preview` пересчитывает альтернативную сумму и/или срок по текущим
правилам и калькулятору ставки. Он только читает данные, даже до приёма в конвейер.
Подробные формы ответа и ошибки: [API_CONTRACT.md](API_CONTRACT.md).
