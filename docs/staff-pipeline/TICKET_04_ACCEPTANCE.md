На настоящем PostgreSQL дополнительно прошёл конкурентный HTTP-сценарий: два открытия
дают один автоотказ и два снимка; две отмены дают 200/409; два решения дают 200/409,
одно активное решение и три снимка. [Результат](CONCURRENCY_TICKET_04.json).

После перезапуска рабочего API заявка №12 осталась COMPLETED, оба снимка сохранились:
[8 проверок после рестарта](RESTART_TICKET_04.json). [HTTP-проверка frontend](FRONTEND_SMOKE_TICKET_04.json) на рабочем
стенде — 34 проверки, без создания заявок и без reset. Сквозная приёмка отдела
выполнена через HTTP API, отдельный браузерный прогон нового интерфейса не проводился.

Исходные 26 строк проверены до и после запуска нового API. Прежние заявки и компании
не перезаписывались. Для живой приёмки создана отдельная синтетическая компания и
заявка №12. `.env`, серверные Compose-файлы и том рабочей PostgreSQL сохранены.
Тестовые контейнеры и сеть удалены; отдельный тестовый volume оставлен для аудита.

## Эксплуатация и границы

Резервная копия: `/opt/delo/backups/staff-t4-20261022/`: исходный dump,
`database-before-switch.dump`, прежний backend и Compose. Прежний образ сохранён
тегом `delo-api:before-staff-t4`. Инструкция выпуска и отката:
[deploy/STAFF_RELEASE.md](../../deploy/STAFF_RELEASE.md).

Новые таблицы не меняют схему прежних таблиц. Новые глобальные статусы, роли и типы
клиентских событий не добавлены; тела исходных ручек сотрудника и клиентский код
не менялись. Общая история клиента не пополняется событиями автоматики: отказ
остаётся в таблице решений и во внутреннем аудите. Рекомендации нового скоринга
приходят отдельным `/scoring`, старый блок карточки сохранён.

Защита истории и снимков действует на уровне ORM, прямой SQL администратора не
ограничивает. Отмена проверяет наличие другой активной заявки, но общая гонка с
созданием клиентской заявки не расширялась за пределы исходного контракта.
В наборе остаётся одно предупреждение зависимостей Starlette/AnyIO, ошибок нет.
