# Карта проекта: бэкенд MVP «Кредит для бизнеса»

Источник требований: «Вся инструкция продукта (клиент)», разделы 1–15.
Дизайн-эталон для фронта: https://delo-credit-design-directions.cheery-tapir-6675.chatgpt.site, **вариант 4**.

## Роли и границы

- В этом репозитории только бэкенд. Фронт делает отдельная команда по `docs/FRONTEND_GUIDE.md` и OpenAPI (`/docs`).
- Срок: 2 дня. Приоритет: сквозной путь нового кредита → решения сотрудника → рефинансирование → «Нужны сведения» → контент.
- Все данные синтетические. Реальные реестры и бюро не запрашиваются.

## Стек и запуск

- Python 3.12, FastAPI, SQLAlchemy 2, Pydantic 2 (+ pydantic-settings), PostgreSQL 16, pytest.
- `docker compose up` поднимает `db` и `api`. При старте выполняется `create_all` (без Alembic) и загружаются сид-данные (идемпотентно).
- Сессия хранится в подписанной httpOnly-cookie (`SameSite=Lax`). Разрешённые источники CORS задаются в `CORS_ORIGINS`, cookie передаются (`allow_credentials`).
- Флаг `BUREAU_AVAILABLE=true|false` переключает симулятор бюро в режим «недоступен».

## Справочники (без переименований)

- `borrowing_mode`: `NEW_CREDIT` («Новый кредит»), `REFINANCE` («Рефинансирование действующего кредита»; на кнопке «Рефинансирование»).
- `product_id` (только для `NEW_CREDIT`):
  - `WORKING_CAPITAL`: «Оборотный кредит», цель «Закупки и текущие расходы»;
  - `EQUIPMENT`: «Кредит на оборудование», цель «Покупка оборудования».
- `legal_form`: `IP`, `OOO`.

## Правила расчёта (`pricing`)

- **Сумма:** от 100 000 ₽, шаг 50 000 ₽. Максимум 3 000 000 ₽ для ИП и 10 000 000 ₽ для ООО.
- **Срок:** 6–36 месяцев, шаг 1.
- **Ставка по рейтингу:**
  - 750–1000 → 18 %;
  - 500–749 → 22 %;
  - 0–499 → 27 %;
  - срок 25–36 месяцев → +2 п.п.;
  - рейтинг недоступен → 24 %, флаг `rating_based=false` (подпись «расчёт без рейтинга»). 600 вместо ошибки не подставляем.
- **Рефинансирование:** ставка = правило выше − 1 п.п. Сумма равна остатку выбранного кредита, клиент её не редактирует.
- **Платёж:** аннуитетный, месячная ставка = годовая / 12, округление до целого рубля.
- **Шкала рейтинга:** 0–499 низкий, 500–749 средний, 750–1000 высокий.

## Модель данных

- `users`: id, login, password_hash, full_name, role
- `companies`: id, owner_id, legal_form, name, ogrn, created_at
- `bureau_ratings`: company_id, score, updated_at
- `existing_loans`: id, company_id, product_id, original_amount, balance, rate, next_payment_amount, next_payment_date
- `applications`:
  - идентификация и владелец: id, number (присваивается при отправке), company_id;
  - что берут: borrowing_mode, product_id, existing_loan_id, amount, term_months;
  - предварительный расчёт: preliminary_rate, preliminary_payment, rating_used;
  - анкета: business_profile (JSON-снимок: industry, months_operating, monthly_revenue, monthly_debt_payments, purpose_details);
  - состояние: current_step, status, created_at, updated_at, submitted_at, decided_at, completed_at.
- `application_events`: id, application_id, type, actor_role, actor_name, payload (JSON), created_at
- `info_requests`: id, application_id, message, requested_fields, answer_text, answer_fields, created_by, answered_at
- `decisions`: id, application_id, kind (`APPROVED|COUNTER_OFFER|REJECTED`), amount, term_months, rate, monthly_payment, comment, reject_reason_code, created_by, is_active, created_at
- `news`: id, tag (`GENERAL|IP|OOO|WORKING_CAPITAL|EQUIPMENT`), title, summary, body

## Машина статусов

```
DRAFT ─submit→ IN_REVIEW ─request_info→ NEED_INFO ─answer→ IN_REVIEW
IN_REVIEW ─approve (параметры = запрошенным)→ APPROVED ─accept→ COMPLETED
IN_REVIEW ─counter_offer→ COUNTER_OFFER ─accept→ COMPLETED
                                         └─supplement→ IN_REVIEW (предложение аннулируется)
IN_REVIEW ─reject→ REJECTED
```

- Любой недопустимый переход или повтор действия → `409 Conflict`.
- Этап шкалы вычисляет сервер:
  - `DRAFT` → нет;
  - `IN_REVIEW`, `NEED_INFO` → «Проверка данных»;
  - `APPROVED`, `COUNTER_OFFER`, `REJECTED` → «Решение»;
  - `COMPLETED` → «Завершение».

  Шаг «Заявка отправлена» отмечен всегда, когда есть `submitted_at`.
- Активные заявки: у компании не больше одной на `NEW_CREDIT` и одной на `REFINANCE`. Один `existing_loan_id` не может быть в двух активных заявках. Активными считаются все статусы, кроме `REJECTED` и `COMPLETED`.

## Правила, закреплённые на сервере

1. Чужая компания, кредит или заявка → `404`.
2. Формат ошибок: `{"error": {"code": "...", "message": "...", "fields": {"field": "текст"}}}`.
3. Суммы хранятся целыми рублями, ставки — `Decimal(4,1)`.
4. При `APPROVED` параметры обязаны совпадать с запрошенными. Отличающиеся условия оформляются только через `COUNTER_OFFER`.
5. Встречное предложение по рефинансированию: сумма от 100 000 ₽ до остатка долга. Если сумма меньше остатка, клиент видит пометку «Оставшуюся часть долга (X ₽) нужно погасить по текущему кредиту».
6. Анкета при отправке сохраняется снимком в заявке и не зависит от последующих правок профиля.
7. ID черновика создаётся сразу. Номер `D-2026-000001` присваивается при отправке.
8. Клиент не видит внутреннюю оценку и рекомендацию.
9. Завершённая заявка не попадает в действующие кредиты: выдача денег не моделируется.

## Внутренняя оценка (видит только сотрудник)

Долговая нагрузка = (monthly_debt_payments + preliminary_payment) / monthly_revenue. Рекомендация:

- рейтинг ≥ 750 и нагрузка < 50 % → «Одобрить»;
- рейтинг < 500 или нагрузка > 80 % → «Отказать»;
- остальное → «На усмотрение сотрудника».

Проверки в карточке сотрудника: регистрация (симулятор), кредитная история (симулятор бюро), полнота анкеты, долговая нагрузка.
