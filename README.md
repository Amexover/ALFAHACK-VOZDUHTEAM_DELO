# Дело — кредитный кабинет для бизнеса

Веб-прототип для хакатона: клиент выбирает компанию и финансирование, сохраняет анкету, отправляет заявку и получает решение. Сотрудник видит проверки, запрашивает сведения, одобряет, предлагает другие условия или отказывает. Все данные синтетические. Принятие предложения завершает демонстрацию; подписания и выдачи денег нет.

Рабочий стенд: http://195.133.41.30. Swagger: http://195.133.41.30/docs. Дизайн — утверждённый вариант 4 (Apple) галереи «Дело».

## Быстрый запуск на обычном ПК

Нужен Docker Engine / Docker Desktop с Docker Compose v2, свободный порт 80 и доступ к реестру образов/npm при первой сборке. Ориентир для сборки на ПК — 2 ГБ свободной RAM. После сборки основной сценарий не требует внешних API.

```sh
cp .env.example .env
# Для публикации замените POSTGRES_PASSWORD и SECRET_KEY в .env.
docker compose up -d --build
```

Открыть http://localhost. Для другого порта задайте WEB_PORT=8080 в .env и откройте http://localhost:8080. Интерфейс и API имеют один origin, cookie передаётся автоматически. Не добавляйте реальных клиентских данных.

|---|---|---|

PostgreSQL хранится в именованном Docker volume. `docker compose down` останавливает комплект без удаления данных. Не используйте `down -v` для сохранения данных. Служебный сброс по умолчанию отключён. `DEMO_TOOLS_ENABLED=true` включает операции без авторизации в существующем backend; включать только на изолированной локальной демонстрации.

## Устройство проекта

- `frontend/`: React 19, TypeScript, Vite, React Router, Lucide. Исходники читаемо отформатированы, версии разрешены в package-lock.json.
- `backend/`: исходный FastAPI backend, PostgreSQL/SQLAlchemy, симуляторы, сид-данные и 32 штатных теста.
- `frontend/nginx.conf`: раздача сборки, SPA fallback и reverse proxy API.
- `docker-compose.yml`: воспроизводимый запуск всего комплекта из исходников.
- `deploy/compose.frontend.yml`: добавление frontend к существующему backend Compose на сервере; нужен Compose >=2.24.4 из-за !override.
- `PRODUCT.md`, `DESIGN.md`: границы продукта и оформление.
- `docs/ARCHITECTURE.md`: архитектура, модель данных и состояния.
- `docs/BACKEND_FRONTEND_GUIDE.md`, `docs/BACKEND_PROJECT_MAP.md`: подробный контракт исходного backend.
- `docs/api-examples/`: 29 примеров TestClient на SQLite, не дамп рабочего PostgreSQL. Образец токена заменён заглушкой.
- `docs/openapi.json`, `docs/Delo.postman_collection.json`: схема и коллекция запросов.
- `docs/ACCEPTANCE.md`: пошаговая приёмка и 5-минутная демонстрация.
- `THIRD_PARTY_NOTICES`: компоненты, лицензии, синтетические источники и смоделированные интеграции.

## Проверка и разработка

```sh
cd frontend
npm ci
npm run dev
# http://127.0.0.1:5173; /api проксируется на демонстрационный сервер.
npm run build
BASE_URL=http://localhost npm run smoke
```

Node.js 22.23.3 используется в Docker-сборке; frontend требует Node >=22.12. Для локального другого API измените target в vite.config.ts. Не храните токен в localStorage: приложение использует httpOnly-cookie того же origin. Ошибки API отображаются рядом с полями; браузерный reload восстанавливает сохранённые серверные шаги, а не несохранённый ввод.

Штатные тесты backend безопасно используют отдельную временную SQLite-базу:

```sh
docker compose exec -e DATABASE_URL=sqlite:///:memory: api python -m pytest -q -p no:cacheprovider
```

`python3 scripts/acceptance.py --isolated` создаёт синтетические заявки только в отдельном комплекте на 127.0.0.1:8081. Скрипт отказывается работать с общим стендом. Это проверка полного процесса на PostgreSQL, а не замена браузерной приёмки.

## Обновление существующего сервера

Сначала собрать frontend локально. Передача: `frontend/` (без node_modules), `deploy/`, документация и исходники. `.env` сервера не копировать и не перезаписывать. Для текущего VPS сборка из готового dist снижает потребление памяти:

```sh
cd /opt/delo
docker compose -f docker-compose.yml -f deploy/compose.frontend.yml build frontend
docker compose -f docker-compose.yml -f deploy/compose.frontend.yml up -d --no-build api frontend
```

На VPS API становится доступен напрямую только по 127.0.0.1:8000, порт 80 получает nginx; /api и /docs остаются доступны снаружи. Не заменяйте существующий docker-compose.yml корневым файлом комплекта без проверки — это два разных способа запуска. Rollback: остановить frontend и запустить исходный backend Compose без override. База и её volume сохраняются.

## Ограничения перед сдачей

Стенд пока без HTTPS. В исходном backend остаются вопросы: публичные demo-операции, целостность анкеты после дополнения, обязательная причина на API, конкурентное создание черновиков, миграции и бэкапы. Интерфейс требует причину и не отправляет пустые необязательные поля, но это не устраняет обход прямым API-запросом. Полный статус требований методички и результаты приёмки — в итоговом отчёте. GitHub-репозиторий и доступ жюри требуют настройки со стороны команды; размещение на VPS их не заменяет.
