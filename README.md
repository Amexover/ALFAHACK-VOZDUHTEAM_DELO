# Дело — кредитный кабинет для бизнеса

Веб-прототип для хакатона: клиент выбирает компанию и финансирование, сохраняет анкету, отправляет заявку и получает решение. Сотрудник видит проверки, запрашивает сведения, одобряет, предлагает другие условия или отказывает. Все данные синтетические. Принятие предложения завершает демонстрацию; подписания и выдачи денег нет.

## Быстрый запуск на обычном ПК

Нужен Docker Engine / Docker Desktop с Docker Compose v2, свободный порт 80 и доступ к реестру образов/npm при первой сборке. Ориентир для сборки на ПК — 2 ГБ свободной RAM. После сборки основной сценарий не требует внешних API.

```sh
cp .env.example .env
# Для публикации замените POSTGRES_PASSWORD и SECRET_KEY в .env.
docker compose up -d --build
```

Откройте http://localhost. Для другого порта задайте `WEB_PORT=8080` в `.env` и откройте http://localhost:8080. Интерфейс и API работают по одному адресу, cookie передаётся автоматически. Не добавляйте реальных клиентских данных.

| Логин | Пароль | Роль |
|---|---|---|
| alexey | demo | Клиент, три компании |
| maria | demo | Другой клиент, проверка изоляции |
| staff | demo | Сотрудник |

Данные PostgreSQL хранятся в именованном томе Docker. `docker compose down` останавливает комплект без удаления данных. Не используйте `down -v`, если нужно сохранить данные. Служебный сброс по умолчанию отключён. `DEMO_TOOLS_ENABLED=true` включает операции без авторизации в существующей серверной части; допускается только на изолированной локальной демонстрации.

## Устройство проекта

- `frontend/`: React 19, TypeScript, Vite, React Router, Lucide. Исходники читаемо отформатированы, версии зависимостей зафиксированы в `package-lock.json`.
- `backend/`: серверная часть FastAPI, PostgreSQL/SQLAlchemy, симуляторы, исходные демонстрационные данные и 32 штатных теста.
- `frontend/nginx.conf`: раздача сборки, поддержка прямых ссылок на страницы приложения и обратное проксирование API.
- `docker-compose.yml`: воспроизводимый запуск всего комплекта из исходников.
- `deploy/compose.frontend.yml`: добавление frontend к существующему backend Compose на сервере; нужен Compose >=2.24.4 из-за !override.
- `PRODUCT.md`, `DESIGN.md`: границы продукта и оформление.
- `docs/ARCHITECTURE.md`: архитектура, модель данных и состояния.
- `docs/BACKEND_FRONTEND_GUIDE.md`, `docs/BACKEND_PROJECT_MAP.md`: подробный контракт исходного backend.
- `docs/api-examples/`: 29 примеров ответов тестового клиента на SQLite; это не копия рабочей базы PostgreSQL. Образец токена заменён заглушкой.
- `docs/openapi.json`, `docs/Delo.postman_collection.json`: схема и коллекция запросов.
- `docs/ACCEPTANCE.md`: пошаговая приёмка и 5-минутная демонстрация.
- `THIRD_PARTY_NOTICES`: компоненты, лицензии, синтетические источники и смоделированные интеграции.

## Проверка и разработка

```sh
cd frontend
npm ci
npm run dev
# http://127.0.0.1:5173; /api проксируется на демонстрационный сервер.
npm run build
BASE_URL=http://localhost npm run smoke
```

Node.js 22.23.3 используется в сборке Docker; клиентская часть требует Node.js не ниже 22.12. Для подключения к другому локальному API измените адрес назначения в `vite.config.ts`. Не храните токен в `localStorage`: приложение использует cookie с атрибутом `httpOnly` на том же адресе. Ошибки API отображаются рядом с полями; после обновления страницы восстанавливаются сохранённые на сервере шаги, но не введённые и ещё не сохранённые значения.

Штатные тесты backend безопасно используют отдельную временную SQLite-базу:

```sh
docker compose exec -e DATABASE_URL=sqlite:///:memory: api python -m pytest -q -p no:cacheprovider
```

`python3 scripts/acceptance.py --isolated` создаёт синтетические заявки только в отдельном комплекте на 127.0.0.1:8081. Скрипт отказывается работать с общим стендом. Это проверка полного процесса на PostgreSQL, а не замена браузерной приёмки.

## Демо на 5 минут

1. Алексей: ИП → рейтинг и кредиты; сменить компанию и показать изменение материалов, открыть полный текст новости.
2. Новый кредит: 1,5 млн/24 месяца → оборудование → анкета → сохранить и продолжить → отправить.
3. Сотрудник: очередь → проверки и рекомендация → запросить выручку с подтверждением.
4. Алексей: ответить в продукте. Сотрудник: предложить 1,2 млн/24 месяца/19,5% с причиной.
5. Алексей: сравнить предложение, принять, обновить страницу; показать историю и отсутствие фактической выдачи.
6. При наличии времени: рефинансирование, отказ, другой пользователь и отсутствие чужих компаний.

## Обновление существующего сервера

Сначала соберите клиентскую часть локально. Передайте `frontend/` (без `node_modules`), `deploy/`, документацию и исходники. Файл `.env` сервера не копируйте и не перезаписывайте. Для текущего VPS сборка из готового каталога `dist` снижает потребление памяти:

```sh
cd /opt/delo
docker compose -f docker-compose.yml -f deploy/compose.frontend.yml build frontend
docker compose -f docker-compose.yml -f deploy/compose.frontend.yml up -d --no-build api frontend
```

На VPS API становится доступен напрямую только по 127.0.0.1:8000, порт 80 получает nginx; `/api` и `/docs` остаются доступны снаружи. Не заменяйте существующий `docker-compose.yml` корневым файлом комплекта без проверки — это два разных способа запуска. Для отката остановите клиентскую часть и запустите исходную конфигурацию Docker Compose без дополнительного файла. База и её том сохраняются.
