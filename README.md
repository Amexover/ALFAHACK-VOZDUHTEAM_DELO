# Дело — кредитный кабинет для бизнеса

Мы сделали веб-приложение для хакатона Альфа-Банка. Предприниматель выбирает свою компанию, подбирает новый кредит или рефинансирование, заполняет анкету и отправляет заявку. Сотрудник банка видит заявку, может запросить дополнительные сведения, одобрить её, предложить другие условия или отказать. Клиент получает ответ в том же кабинете.

Это демонстрационный проект: все пользователи, компании и кредиты вымышленные. Реальной проверки в бюро, подписания договора и выдачи денег здесь нет.

## Как запустить

Нужен установленный Docker с Docker Compose v2, свободный порт 80 и примерно 2 ГБ свободной оперативной памяти для сборки. При первом запуске Docker скачает нужные образы и зависимости.

В папке проекта выполните:

```sh
cp .env.example .env
docker compose up -d --build
```

После сборки откройте [http://localhost](http://localhost). Если порт 80 занят, укажите в `.env` `WEB_PORT=8080` и откройте [http://localhost:8080](http://localhost:8080).

В `.env` можно изменить пароль базы (`POSTGRES_PASSWORD`) и ключ приложения (`SECRET_KEY`). Перед размещением проекта в интернете их обязательно нужно заменить. Для демонстрации используйте только вымышленные данные.

## Что можно попробовать

1. Войти за Алексея, выбрать компанию и посмотреть её рейтинг, кредиты и новости.
2. Нажать «Взять новый кредит», выбрать сумму, срок и продукт, заполнить анкету и отправить заявку.
3. Войти за сотрудника, открыть заявку и запросить уточнение или предложить другие условия.
4. Снова войти за Алексея, ответить на запрос и принять предложение. После обновления страницы статус и история заявки сохранятся.
5. Отдельно попробовать рефинансирование и войти за Марию: она должна видеть только свои компании и заявки.

Более точный сценарий с конкретными суммами и ожидаемыми результатами есть в [документе по проверке](docs/ACCEPTANCE.md).

## Из чего состоит проект

Бэкенд ИИ-помощника под Qwen3.8-27B: клиентский и служебный режимы, диалоги,
потоковые ответы, поиск по базе знаний и инструменты чтения банковских данных.
Подключение модели, запуск на GPU и контракт для фронтенда — в
[инструкции помощника](docs/ASSISTANT_BACKEND.md). По умолчанию инференс отключён;
для него нужен отдельный сервер с моделью.

- `frontend/` — интерфейс клиента и сотрудника на React и TypeScript;
- `backend/` — API на FastAPI, расчёты, статусы заявок и тестовые данные;
- PostgreSQL — хранит компании, заявки и историю действий;
- `docker-compose.yml` — запускает всё вместе.

Схема приложения и переходы между статусами описаны в [архитектуре](docs/ARCHITECTURE.md). Запросы к API можно посмотреть в [OpenAPI](docs/openapi.json) и [коллекции Postman](docs/Delo.postman_collection.json). Использованные библиотеки и источники перечислены в [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES).

## Как проверить сборку

Фронтенд ИИ-помощника: [возможности, запуск и браузерные тесты](docs/ASSISTANT_FRONTEND.md).

После запуска Docker тесты серверной части выполняются из корня проекта:

```sh
docker compose exec -e DATABASE_URL=sqlite:///:memory: api python -m pytest -q -p no:cacheprovider
```

Сборка интерфейса и быстрая проверка работающего приложения:

```sh
cd frontend
npm ci
npm run build
BASE_URL=http://localhost npm run smoke
```

Для этих команд нужен Node.js версии не ниже 22.12. Если приложение открыто на порту 8080, в последней команде укажите `BASE_URL=http://localhost:8080`.

Остановить проект можно командой `docker compose down` из корня проекта. Заявки останутся в томе PostgreSQL и будут доступны после следующего запуска. Команда `docker compose down -v` удалит том вместе с данными.
